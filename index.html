Turning field-visit data into a monthly incentive scorecard

A Power BI semantic model that tracks how every Market Demand Officer (MDO) and Territory Manager (TM) performs against monthly targets, and who qualifies for incentives.

Report pages

Three views serve different readers. The first is a single-screen page built for the Chairman and Managing Director (CMD), so everything can be read at a glance. The other two give managers more detail by zone and by company.

The problem

Field officers log farmer contacts, retailer visits and training programs in a CRM. Targets live separately in Excel files on SharePoint. The goal was one view that shows, at any point in the month, whether each officer is on pace and who qualifies for incentives.

What I built

One star-style model joining CRM activity, targets and the org hierarchy (company, zone, region, territory, HQ). Every officer gets an actual-versus-target view, month-to-date and full month, across three KPIs, plus an automatic "Eligible" flag.

Three KPIs

Farmer contacts, retailer visits and Subeej activity (Subeej is a farmer-meeting program), each with its own target and achievement %. Farmer contacts are built from four sources: farmer visits, missed-call follow-ups, manual entries and Subeej activity.

Pro-rated MTD targets

Targets scale by days elapsed in the selected month, so mid-month numbers are fair.

Incentive logic

An MDO is eligible only when all three KPIs reach 100% of the MTD target. TMs qualify at 100% of their full-month visit target, and joint visits with MDOs count towards it.

Month comparison

A disconnected offset table lets one visual compare the current month with 1, 2 or 3 months back. The CMD page uses it for its last-3-months charts.

Salesforce data integration

The CRM data behind the MDO model comes from Salesforce. I built a shared Power BI dataflow that prepares seven tables and feeds the semantic model, so reports read ready-made data instead of calling Salesforce directly. On 4 October 2026 the model held about 5 million rows from it, measured with DAX Studio. The count grows as new records arrive.

  1. Connect with the Power BI Salesforce connector and pick only the tables needed: users, profiles, visits, activity lines and sub-lines, and retailer training.
  2. Keep only the required columns and limit rows to the current financial year, so volumes stay manageable.
  3. Flatten related records into ordinary columns, so the model receives simple tables.
  4. Turn on incremental refresh on the last-modified date for the five activity tables (users and profiles refresh in full). History is kept, and each refresh reloads only rows changed in the last 5 days.
  5. The semantic model reads from the dataflow on its schedule and feeds the reports and the email automation described later.

Data model

A single user table (User Report) acts as the hub. Visits, activities, manual entries, missed calls, retailer training and targets all join to it on the composite key. Facts also join to one shared date table, and a small activity-name table lets one slicer filter three fact tables. Profile and company are lookups.

Technical highlights

Pro-rated month-to-date target

Returns the full target for a completed month and a daily share for a partial one.

Ret MTD Tgt =
VAR SelectedDays   = COUNTROWS(VALUES(DateTable[Date]))
VAR TotalDaysInMonth = DAY(EOMONTH(MAX(DateTable[Date]), 0))
VAR MonthlyTarget  =
    CALCULATE(SUM(Targets[Retailer Targets]),
        TREATAS(VALUES(DateTable[MonthKey]), Targets[MonthKey]),
        Targets[Profile] = "Market Demand Officer (MDO)")
RETURN
    IF(SelectedDays = TotalDaysInMonth, MonthlyTarget,
       DIVIDE(MonthlyTarget * SelectedDays, TotalDaysInMonth))

Targets are monthly and the date table is daily, so TREATAS bridges them through a MonthKey instead of a physical relationship.

Rolling comparison with a disconnected table

Ret Dynamic =
VAR _Offset = SELECTEDVALUE(MonthOffset[Offset], 0)
VAR _Start  = EDATE(CALCULATE(MIN(DateTable[Date]), ALLSELECTED(DateTable[Date])), _Offset)
VAR _End    = EDATE(CALCULATE(MAX(DateTable[Date]), ALLSELECTED(DateTable[Date])), _Offset)
RETURN
    CALCULATE([Ret Act], REMOVEFILTERS(DateTable[Date]),
              DATESBETWEEN(DateTable[Date], _Start, _End))

The same date window shifts back by N months, so "same days, last month" comparisons stay like-for-like.

Incentive flag

Incentive =
IF([%Ret MTD] >= 1 && [%FC MTD] >= 1 && [%Subeej MTD] >= 1,
   "Eligible", BLANK())

Counted per officer with FILTER(VALUES('User Report'[Key]), ...), then divided by headcount for an eligibility rate. Vacant positions are tracked separately so they do not distort percentages.

Automating report delivery

Management wanted a snapshot of the dashboard in the email body, and the analysis team wanted the matrix in Excel for their own analysis. As the organisation is still moving to Power BI, the interactive report is also published to a website or portal, so anyone can open it in a browser. I built a Power Automate flow that handles all of this. It runs twice a day, after the 6 am and 6 pm refreshes.

The constraint. On a Premium Per User licence, the export-to-file option for Power BI reports was not available to me, and email delivery from a Power BI subscription was not working. So a subscription saves a PDF of the overview page to OneDrive, and the flow takes it from there.

  1. After each scheduled refresh of the semantic model (6 am and 6 pm), a Power BI data alert fires and starts the flow, and the flow records the trigger time.
  2. A Power BI subscription, timed after the refresh, saves the overview page as a PDF in OneDrive.
  3. The flow checks the OneDrive folder every 5 minutes, for up to an hour, until the newest PDF was modified after the trigger time. This stops an old file from being sent.
  4. The PDF is converted to a JPG, and a timestamped copy is archived in OneDrive.
  5. I built a paginated report that mirrors the matrix table, and the flow exports it to Excel, so the team gets the same layout in a file they can analyse further.
  6. The team gets one email: the snapshot inline in the body, the Excel file attached, and a link to the interactive report. The subject carries the report month and the time in India Standard Time.
  7. If no fresh PDF appears within the hour, the run is cancelled and nothing is sent.
Do until:
@greater(
    ticks(outputs('Get_file_metadata_using_path')?['body/LastModified']),
    ticks(variables('AlertTriggerTime')))
Limit: 60 attempts or 1 hour, with a 5-minute delay between checks

Impact

Automating refresh and distribution through Power BI Service cut report preparation time by about 60% in this role, and Row-Level Security keeps access governed. Managers can see officer performance against pro-rated targets at any point in the month, and incentive eligibility is calculated by the model. The report email reaches about 40 people twice a day, and I maintain four dashboards, with more on the way.
